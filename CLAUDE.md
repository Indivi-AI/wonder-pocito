# Pocito

@3rd-party/wonder/CLAUDE.md

Pocito is a Wonder solution: applets, a Marketplace server, an Agno agent server and the on-prem infrastructure around them.
Keep lines at or below 180 characters and use ESM only. Do not use `safeEditTgpComp`; edit normally with read/edit/write tools.

## Layout

- `ui/` the applets and their TGP comps; the entry applet is `ui/wonder-agents.js`. `ui/examples/` holds the guide comps referenced below.
- `marketplace-server/` FastAPI Marketplace; `marketplace-server/marketplace-schema/` is shared with `agno-server/` (Agno AgentOS).
- `e2e-tests/` every test: `main.js` imports all suites and is the developer entry point; `dev/` runs against the dev stack, `prod/` against a
  production image; `traveling-test/` holds fixtures and the Marketplace seed.
- `infra/dev/` the launcher (`main.js`), the dev server (`server.js`), the FLAPI proxy and mock, the LiteLLM config and `container/` (air-gapped image kit).
  `infra/gateway.js` is the same-origin gateway used by dev and prod. `infra/prod/` the production server (`main.js`), images, Helm chart, deploy script and
  docs. `infra/export/` the export scripts and their kits.
- `3rd-party/` is generated by Wonder's `npm run create-solution-repo` from `solution.json`: the import closure of Wonder and jb6. Never edit it; change the
  mother repo and regenerate (`3rd-party/VERSIONS.json` records the source commit).
- Import Wonder only through `@wonder/`, siblings relatively; no file spells a directory of the mother repo (the generator refuses it).
  Comps are published with their served-url layout (`shareImports` in the applet def), so no published code depends on repository directories.

## Scripts

## Registered ReactComp anatomy

```js
import { dsls } from '@jb6/core'
import '@jb6/react'
const { react: { ReactComp, 'react-comp': { comp } } } = dsls

ReactComp('example', {
  params: [{id: 'roomWUrl', as: 'string'}],
  impl: comp({
    hFunc: (ctx, {}, {roomWUrl}) => {
      const { h, useState } = ctx.vars.react
      return function Example() {
        const [value, setValue] = useState('')
        return h('input', { value, onInput: event => setValue(event.target.value) })
      }
    }
  })
})
```

Register every TGP component with `Data`, `Workflow`, `ReactComp`, or a similar constructor; never export or keep a global unregistered profile.
Use the DSL registry to reference components: `dsls.react['react-comp'].example`.
Before editing, read the focused examples in `ui/examples/`: `wfetch2-guide-react-comp.js` (GET, seed, immutable update, PUT),
`json-file-import-guide-react-comp.js` (file input and normalization) and `enrich-ctx-guide-react-comp.js` (context enrichment before a workflow).
Then use `room-state-react-comp.js`, `stable-chat-react-comp.js` and `llm-flow-react-comp.js` for complete patterns.

## Hooks and stable identity

Call hooks only inside the React function returned by `hFunc`.
A child `hFunc` may directly return a props function and call hooks inside that returned function.
Never define a component inside a stateful component and render it with `h`; it gets a new identity on every parent render.
That remount destroys the textarea and causes focus loss or chat collapse.
Register stateful children separately and render them with `hh`: `hh(ctx, dsls.react['react-comp'].stableChild, { value, setValue })`.
The composer in `stable-chat-react-comp.js` owns its textarea hook and stable identity; Enter sends while Shift+Enter inserts a newline.

## Real room persistence

```js
const response = await jb.wonderUtils.wfetch2(assetUrl, { method: 'GET' }, ctx)
const value = response.ok ? await response.json() : seed
await jb.wonderUtils.wfetch2(assetUrl, { method: 'PUT', body: JSON.stringify(value), headers: {'content-type': 'application/json'} }, ctx)
```

If GET is missing, PUT the seed once, then use it as state.
The reusable registered implementation is `data<common>pocitoRoomJsonStore`; load in `useEffect`, then set state and PUT the same immutable object.
Add with `[...items, item]`, edit with `items.map`, and delete with `items.filter`. Never mutate room assets, messages, reports, tags or nested arrays in place.
Bare room ids normalize to public `room://`; public applets use `/room/:roomId/applet/:appletId`.
Signed storage must be explicit with `signedRoom://` and uses `/signed-room/:roomId/applet/:appletId`; do not probe storage to guess whether a room is signed.
Local MinIO examples deliberately use `room:minio//` and isolated room ids.

## Real `llm-flow`

Build the grounded payload from the selected plugin and only its connected assets. Include all room reports so returned ids can be validated and embedded.
Use `ctx.setVars` for ordinary scoped values. Call `extendWithWorkflowVars` only at the boundary immediately before `calcWorkflow`:

```js
const workflowCtx = await jb.workflowUtils.extendWithWorkflowVars(ctx.setVars({
  userMessage, selectedPlugin: JSON.stringify(plugin), accumulatedContext: { chatHistory },
  assetRepoText: JSON.stringify({ plugin, skills, tools, subagents, reports }), llmProxyUrl: globalThis.LLM_PROXY_URL
}))
const result = await dsls.ai.workflow.wonderPlatformAgent.$run().calcWorkflow(workflowCtx)
```

Do not guess another enrichment API and do not replace this with `ctx.run(profile)`.
`dynamic: true` parameters are delayed callables bound to their lexical context; call such a parameter as `param(ctx)`.
The workflow returns structured data in `result.runRes` plus `workflowTrace` and `workflowErrors`.
Normalize `runRes` to `{text, reportIds, followUps}` and derive displayed trace steps from `workflowTrace`.
Append one user message, run the workflow, append one agent message, then persist the resulting conversation.
Before rendering an id, find it in `repo.reports`, ignore missing ids, and render the real report rather than copied data.

## On-prem development-container verification

The air-gapped dev image `pocito-dev:latest` contains dependencies, sudo and the OMP binary. Clone the exported Git bundle on Linux and bind-mount that
checkout at `/workspace/repo`. The entrypoint requires the checkout and never clones or updates it; `omp` runs its launcher from the checkout.
SSH starts automatically on port 2222. Publish a host port such as `5555:2222` and connect as `pocito`; SSH and sudo need no credentials in this dev image.
MinIO remains external. PostgreSQL 17 with pgvector starts locally when Agno is local and `PGVECTOR_URL` is empty; a configured URL always uses that database.
Bundled PostgreSQL stores data under `/home/pocito/.local/share/pocito/postgres` (override with `PGDATA`) and stops with the launcher.
Pass service configuration with Docker `--env-file`. If bundled LiteLLM is used, mount its ignored YAML outside the checkout and set `LITELLM_CONFIG` to that
container path. Never put provider keys in the Git bundle, tracked template, build arguments, or image layers.
Inside the image `npm run local` requires external FLAPI and uses the image's `/workspace/node_modules` and `/opt/pocito/venvs`; do not put `node_modules`
in the host checkout. Marketplace data, PostgreSQL data, OMP state and SSH keys live under `/home/pocito`; a home volume is optional.
The exact export, host clone, permissions, run, update and migration commands are in `README.md` and the exported `infra/export/images/README.md`.

Run all HeavyTest cases at `http://localhost:3000/studio/tests.html?pattern=pocitoOnPrem&includeHeavy`.
The `pocitoOnPrem.*` tests only verify that Wonder, Marketplace/MinIO, Agno, LiteLLM and FLAPI are configured and reachable.
Functional checks use the separate `pocitoIntegration.*` namespace; `pocitoProd.*` verifies a running production image.
For focused diagnosis call `runTest` with the exact test id and inspect `onPremErrors` plus each relevant domain logger's error array.
A green page is an installation/integration signal, not exhaustive product-quality validation.
